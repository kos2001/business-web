# 샘플 계약서

`docs/examples.md` 를 만들 때 쓴 입력입니다. 실재하지 않는 회사·조건으로 지어낸
문서이고, 워크스페이스를 처음 열어 보거나 플레이북을 고친 뒤 결과가 달라졌는지
비교할 때 쓰라고 남겨 둡니다.

### 선례로 넣을 것 (코퍼스)

조건을 **일부러 서로 다르게** 만들었습니다. 전부 같은 값이면 "지난번엔 어떻게
합의했나"를 물어볼 이유가 없고, 코퍼스의 값은 바로 그 범위에서 나옵니다.

| 파일 | 지연배상 | 그 외 |
|---|---|---|
| `표준공급계약서_2026.docx` | 일 0.1% · 상한 10% | 우리 표준. 검수 10영업일, 배경 IP 유보, 책임 상한 |
| `B사_장기공급계약_2025.docx` | 일 0.15% · 상한 12% | 물량 약정 6만개, 원자재 지수 연동 단가 조정 |
| `A사_공급계약_2025.docx` | 일 0.2% · 상한 15% | **우리가 양보한 최대치.** 하자보수 18개월 |
| `C사_NDA_2026.docx` | — | 상호 대칭 NDA, 종료 후 3년 |

넷을 다 넣으면 협상 대책이 후퇴선 세 단계를 각각 다른 선례에 매핑합니다 —
최초안은 표준, 1차 후퇴는 B사, 최종선은 A사(우리 최대치). 그 범위를 넘는 순간
`근거 필요` 로 멈춥니다.

### 검토 대상

| 파일 | 무엇 |
|---|---|
| `공급계약서_한빛_불리.docx` | 상대 초안. 지연배상 일 2.5% 무상한, 무기한 검수·품질보증, 배경 IP 귀속, 사유 불문 7일 해지, 일방 관할. 단가표 포함(표 파싱 확인용). |

## 해보기

1. **계약서 분석** 워크스페이스에서 선례 4건을 차례로 올리고 첨부 칩의
   "선례로 추가" 를 누릅니다. (표준 1건만 넣어도 동작하지만, 넷을 다 넣어야
   후퇴선이 단계별로 다른 근거를 갖습니다.)
2. `공급계약서_한빛_불리.docx` 를 올리고 "을 관점에서 검토해 줘" 라고 합니다.
3. **협상 대책** 에서 계약금액과 목표 마진을 함께 주면 최종선이 계산됩니다.
   주지 않으면 `근거 필요` 로 남는데, 그게 맞는 동작입니다.
4. **계약서 작성** 에서 합의 내용을 부속합의서로 옮깁니다.
